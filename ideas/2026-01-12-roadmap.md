### 1.1 ALB Security Group WAF Bypass

**Problem**: The ALB accepts traffic from `0.0.0.0/0`, allowing attackers to bypass CloudFront WAF by hitting the ALB directly. ALB DNS can be enumerated via Certificate Transparency logs.

**Location**: `lib/constructs/ingestion-service.ts`

**Current Code**:

```typescript
albSecurityGroup.addIngressRule(
  ec2.Peer.anyIpv4(), // VULNERABLE
  ec2.Port.tcp(80),
  "Allow HTTP from anywhere",
);
```

**Implementation**:

1. Look up the CloudFront managed prefix list ID for your region:
   ```bash
   aws ec2 describe-managed-prefix-lists --filters "Name=owner-id,Values=AWS" \
     --query "PrefixLists[?PrefixListName=='com.amazonaws.global.cloudfront.origin-facing'].PrefixListId"
   ```
2. Update the security group to use the prefix list:

   ```typescript
   // Option A: Use CDK's Peer.prefixList (preferred)
   albSecurityGroup.addIngressRule(
     ec2.Peer.prefixList("pl-3b927c52"), // CloudFront prefix list (us-east-1)
     ec2.Port.tcp(80),
     "Allow HTTP from CloudFront only",
   );

   // Option B: If using custom domain with HTTPS
   albSecurityGroup.addIngressRule(
     ec2.Peer.prefixList(cloudFrontPrefixListId),
     ec2.Port.tcp(443),
     "Allow HTTPS from CloudFront only",
   );
   ```

3. Remove the `anyIpv4()` rule entirely

**Verification**:

1. Deploy the change to a dev/staging environment
2. Get the ALB DNS name from AWS Console or `aws elbv2 describe-load-balancers`
3. Attempt to curl the ALB directly: `curl -v http://<alb-dns>/health`
4. Verify the request is rejected (connection timeout or refused)
5. Verify requests through CloudFront still work: `curl -v https://api-dev.argus.pw/health`

**Effort**: 1 hour

**Location**: `lib/constructs/workers.ts`

**Current Code**:

```typescript

```

**Implementation**:

1. Increase reserved concurrency for matching worker:

   ```typescript
   // lib/constructs/workers.ts
   const matchingWorker = new lambda.Function(this, "MatchingWorker", {
     // ...
     reservedConcurrentExecutions: isProd ? 500 : 50,
   });
   ```

2. Add CloudWatch alarm for concurrency saturation:

   ```typescript
   // lib/constructs/workers.ts (add after function definition)

     threshold: isProd ? 400 : 40, // 80% of reserved
   ```

3. Consider similar increases for profile updater (100 → 200)

**Verification**:

1. Deploy to staging

   - `AWS/Lambda/ConcurrentExecutions` should stay below 80% of reserved

### 1.3 Mutation Gate Race Condition

**Problem**: Classic TOCTOU (Time-Of-Check-Time-Of-Use) bug. `checkMutationGate()` reads, then `setMutationGate()` writes. Two concurrent requests for the same device will both pass the check.

**Location**: `src/services/profile/profile-service.ts`

**Current Code**:

```typescript
async checkMutationGate(deviceId: string): Promise<boolean> {
  const key = `recently_updated:${deviceId}`;
  const exists = await this.deps.redis.exists(key);  // READ
  return exists === 0;
}

async setMutationGate(deviceId: string): Promise<void> {
  const key = `recently_updated:${deviceId}`;
  await this.deps.redis.setex(key, this.deps.config.mutationGateTtlSeconds, "1");  // WRITE
}
```

**Implementation**:

1. Replace the two methods with a single atomic operation:

   ```typescript
   /**
    * Attempts to acquire the mutation gate for a device.
    * Uses atomic SET NX to prevent race conditions.
    * @returns true if gate was acquired (caller should proceed with update)
    * @returns false if gate already held (caller should skip update)
    */
   async tryAcquireMutationGate(deviceId: string): Promise<boolean> {
     const key = `recently_updated:${deviceId}`;
     // SET key "1" NX EX ttl - returns "OK" if set, null if key exists
     const result = await this.deps.redis.set(
       key,
       "1",
       "EX",
       this.deps.config.mutationGateTtlSeconds,
       "NX"
     );
     return result === "OK";
   }
   ```

2. Update `processProfileUpdate()` to use the new method:

   ```typescript
   async processProfileUpdate(device_id: string, fingerprint: Fingerprint): Promise<ProfileUpdateResult> {
     // Atomic check-and-set
     const acquired = await this.tryAcquireMutationGate(device_id);
     if (!acquired) {
       return { skipped: true, reason: "mutation_gate" };
     }

     // No separate setMutationGate() call needed - already set by tryAcquire
     // ... rest of method
   }
   ```

3. Remove or deprecate the old `checkMutationGate()` and `setMutationGate()` methods

**Verification**:

1. Unit test with concurrent calls:

   ```typescript
   it("should only allow one concurrent update per device", async () => {
     const results = await Promise.all([
       service.tryAcquireMutationGate("device-123"),
       service.tryAcquireMutationGate("device-123"),
       service.tryAcquireMutationGate("device-123"),
     ]);

     const acquired = results.filter((r) => r === true);
     expect(acquired.length).toBe(1);
   });
   ```

2. Integration test with actual Redis:
   - Fire 100 concurrent requests for same device_id
   - Verify only 1 profile write occurs
   - Check `MutationGateSkip` metric count = 99

**Effort**: 1 hour

   ```json
     },
     "previous": {
       "ENCRYPTION_KEY": "base64...",
       "HMAC_KEY": "base64...",
       "created_at": "2026-01-11T00:00:00Z"
     }
   }
   ```

2. Create or update `src/services/encryption/decrypt.ts`:

   ```typescript
   export async function decrypt(envelope: EncryptedEnvelope): Promise<Buffer> {
     const secrets = await getSecrets();

     // Try current key first
     try {
       return decryptWithKey(envelope, secrets.current.ENCRYPTION_KEY);
     } catch (decryptError) {

     }
   }
   ```

   ```go
   func corsMiddleware(next http.Handler) http.Handler {
     return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
       // /v1/collect is fire-and-forget with no credentials
       // Safe to allow any origin
       origin := r.Header.Get("Origin")
       if origin != "" {
         w.Header().Set("Access-Control-Allow-Origin", origin)
         w.Header().Set("Access-Control-Allow-Methods", "POST, OPTIONS")
         w.Header().Set("Access-Control-Allow-Headers", "Content-Type, X-Tenant-ID")
         w.Header().Set("Access-Control-Max-Age", "86400")
       }

       // Handle preflight
       if r.Method == http.MethodOptions {
         w.WriteHeader(http.StatusNoContent)
         return
       }

       next.ServeHTTP(w, r)
     })
   }
   ```

### 2.1 Fingerprint Input Validation

**Problem**: Go service accepts `fingerprint` as raw JSON without size or schema validation. Malicious payloads (deeply nested, 10MB) propagate to Lambda workers.

**Location**: `cmd/ingestion/main.go`

**Implementation**:

```go
const (
    maxBodySize     = 64 * 1024  // 64KB max payload
    maxNestingDepth = 10         // Prevent deeply nested JSON
)

func collectHandler(w http.ResponseWriter, r *http.Request) {
    // 1. Limit body size at read time
    r.Body = http.MaxBytesReader(w, r.Body, maxBodySize)

    // 2. Decode with strict settings
    var payload FingerprintPayload
    decoder := json.NewDecoder(r.Body)
    decoder.DisallowUnknownFields()

    if err := decoder.Decode(&payload); err != nil {
        if strings.Contains(err.Error(), "request body too large") {
            http.Error(w, "payload too large", http.StatusRequestEntityTooLarge)
            return
        }
        http.Error(w, "invalid JSON", http.StatusBadRequest)
        return
    }

    // 3. Validate session_id
    if payload.SessionID == "" {
        http.Error(w, "missing session_id", http.StatusBadRequest)
        return
    }

    // 4. Validate fingerprint is an object (not string/array/null)
    if len(payload.Fingerprint) < 2 || payload.Fingerprint[0] != '{' {
        http.Error(w, "fingerprint must be an object", http.StatusBadRequest)
        return
    }

    // 5. Optional: validate nesting depth
    if !validateJsonDepth(payload.Fingerprint, maxNestingDepth) {
        http.Error(w, "fingerprint too deeply nested", http.StatusBadRequest)
        return
    }

    // ... rest of handler
}

func validateJsonDepth(data []byte, maxDepth int) bool {
    depth := 0
    for _, b := range data {
        switch b {
        case '{', '[':
            depth++
            if depth > maxDepth {
                return false
            }
        case '}', ']':
            depth--
        }
    }
    return true
}
```

**Verification**:

### 2.2 FNV-1a Implementation Consolidation

**Problem**: Three different FNV-1a implementations with different algorithms. The middy-helpers version uses a multiplication approximation that produces different hashes.

**Locations**:

- `src/helpers/middy-helpers.ts` - WRONG (uses addition approximation)
- `src/services/matching/matching-service.ts` - Correct
- `src/services/bloom/bloom-filter.ts` - Correct (but unused)

**Implementation**:

1. Create single source of truth `src/helpers/hash.ts`:

   ```typescript
   import { FNV1A_OFFSET_BASIS, FNV1A_PRIME } from "./constants";

   /**
    * FNV-1a hash algorithm (32-bit)
    * @see https://en.wikipedia.org/wiki/Fowler-Noll-Vo_hash_function
    */
   export function fnv1a(str: string): number {
     let hash = FNV1A_OFFSET_BASIS;
     for (let i = 0; i < str.length; i++) {
       hash ^= str.charCodeAt(i);
       hash = Math.imul(hash, FNV1A_PRIME);
     }
     return hash >>> 0; // Convert to unsigned 32-bit
   }
   ```

2. Update all call sites to import from `src/helpers/hash.ts`

3. Delete duplicate implementations

4. Add reference to FNV spec in constants:
   ```typescript
   // src/helpers/constants.ts
   /**
    * FNV-1a hash constants
    * @see https://en.wikipedia.org/wiki/Fowler-Noll-Vo_hash_function
    * @see http://www.isthe.com/chongo/tech/comp/fnv/
    */
   export const FNV1A_OFFSET_BASIS = 2166136261;
   export const FNV1A_PRIME = 16777619;
   ```

**Verification**:

1. Unit test consistency:

   ```typescript
   it("should produce consistent hashes", () => {
     const testCases = [
       { input: "", expected: 2166136261 },
   ```
